# Перспективные направления

**Языки**: [English](FUTURE.md) · [Deutsch](FUTURE.de.md) · Русский (этот файл)

Идеи о том, что можно построить дальше поверх этой демо-версии. Каждый
пункт помечен своим **источником**:

* **[code]** — естественно вырастает из уже существующего кода
  (каркас уже есть в репозитории; в пункте указано, чего не хватает)
* **[roadmap]** — перенесено из roadmap README репозитория
  (более крупные функции, некоторые уже наполовину набросаны)

Пункты раздела *Дальние* намеренно кратки: достаточно одного названия,
чтобы понимать, что искать, — детали всё равно придётся исследовать,
когда возникнет нужда.

Это не список обязательств. Используйте его для выбора направления;
`MODULES.md` говорит, какой модуль затронет каждое направление.

## Ближайшая перспектива — небольшие изменения в существующем коде

### 1. Перетаскивание панелей мышью [code]

* **Есть**: `LayoutEngine.move(id, to)` (core-scene), выбор панели через
  `RayCursor`, события перетаскивания уже направлены на вращение модели,
  когда модель выбрана.
* **Не хватает**: состояния `DRAGGING_PANEL` — когда прицел попадает по
  панели (а не по модели), перетаскивание двигает её в плоскости обзора
  вместо вращения обзора/модели.
* **Затрагивает**: `:app` (`wireTouch`/`handleGesture`), возможно, один
  хелпер в `core-scene`.

### 2. Реализовать `DisplayController` для Rokid [code]

* **Есть**: контракт `DisplayController`, null-объект
  `UnavailableDisplay`, канал сырого HID внутри `RokidMaxBridge`, HUD.
* **Не хватает**: настоящего HID-отчёта для яркости / режима 2D-3D,
  виджетов HUD для управления им (ползунок в панели переиспользовал бы
  виджеты B4/B5).
* **Затрагивает**: только `core-bridge` — остальная часть приложения уже
  видит этот интерфейс.

### 3. Физика: события столкновений + запросы raycast [roadmap]

* **Есть**: `PhysicsWorld` с телами на каждый объект; хват/бросок
  доказывает, что обработка контактов работает.
* **Не хватает**: колбэка `onContact(idA, idB, impulse)`, выводимого в
  приложение, и `raycast(origin, dir) → (id, point, normal)` — двух
  примитивов, нужных любой игре/взаимодействию.
* **Затрагивает**: `core-physics` + демо-хук в `:app`.

### 4. Импорт OBJ [roadmap]

* **Есть**: **экспорт** OBJ (`toObj`), импорт STL как паттерн-адаптер
  (`StlParser` → `GltfModel`), сканирование файлов уже включает
  `.obj`? — нет: `MODEL_EXTENSIONS = {glb, gltf, stl}`.
* **Не хватает**: `scene/obj/ObjParser.kt` (positions + normals + uvs,
  `mtllib` опционально), добавить `"obj"` в `MODEL_EXTENSIONS`.
* **Затрагивает**: `core-scene` (+1 JVM-тест), одна строка в `:app`.

### 5. Тонмаппинг / HDR bloom [roadmap]

* **Есть**: пост-обработка явно **выключена** в `renderLoop`
  (`v.isPostProcessingEnabled = false`) с комментарием, почему
  (unlit-оттенки созданы в display-пространстве); emissive-карты уже
  рендерятся.
* **Не хватает**: снова включить ACES + bloom, перенастроить unlit-цвета
  панелей под новую передаточную функцию.
* **Затрагивает**: только `core-render`. Риск: каждую существующую
  визуальную вещь придётся перепроверить — делайте это в последнюю
  очередь, а не первой.

### 6. Экспорт сцены — всё рабочее пространство [roadmap]

* **Есть**: пофайловый экспорт GLB с проверенным round-trip; песочница
  уже отслеживает id/преобразование/масштаб каждого объекта.
* **Не хватает**: писателя, который порождает **один** glTF с N узлов
  (по одному на `ModelObject`) + преобразованиями; пути импорта,
  восстанавливающего список сцены вместо его замены.
* **Затрагивает**: `core-scene` (экспортёр), `:app` (вход
  загрузки/сохранения).

### 7. Голосовое управление (офлайн STT) [roadmap]

* **Есть**: каждая функция уже представляет собой один вызов
  (`toggleVideo`, `spawnClone`, `togglePhysics`, перецентровка…),
  обработчик клавиш — один `when`.
* **Не хватает**: движка STT (например, Vosk / Whisper.cpp Android),
  распознавателя, сопоставляющего фразы с этими же вызовами.
* **Затрагивает**: новый модуль `core-voice` + одна точка связывания в
  `:app`. Перецентровка/экспорт/переключение источника без рук —
  естественная первая демонстрация.

### 8. UX с упором на геймпад/клавиатуру + оверлей сочетаний [roadmap]

* **Есть**: `GestureRecognizer` уже сопоставляет DPAD/L1/R1/ENTER/
  BUTTON_A; `NavigationState` отслеживает фокус.
* **Не хватает**: панели-справки со списком сочетаний (переиспользует
  растеризатор виджетов), полного паритета с геймпадом, экранных
  индикаторов фокуса.
* **Затрагивает**: `core-input`, одна панель в `:app`.

## Среднесрочная перспектива — функции, требующие настоящей работы над дизайном

### 9. Фаза C: пространственный веб-браузинг [roadmap]

* **Есть**: панели — это текстурированные quad'ы с попаданием по UV;
  WebView, нарисованный в текстуру панели, — тот же конвейер, что и
  `PanelUiDrawer`; roadmap README называет PC-компаньон:
  `verto-display-driver` (Python-агент `vdd` по LAN) для демонстрации
  рабочего стола.
* **Не хватает**: цикла `WebView → Bitmap → updatePanelUi` (WebView
  должен жить в главном потоке; ограничивайте частотой обновления
  панели), пересылки ввода (клики уже приходят как u/v — направляйте в
  `WebView.touch`), жестов прокрутки и агента `vdd` для стриминга с ПК.
* **Затрагивает**: новый `core-web` + панель в `:app`. Это самая крупная
  функция «окно в другой мир», которую может вместить система панелей.

### 10. Пространственное аудио для видео [roadmap]

* **Есть**: `StreamPlayer` владеет Media3 (единственный модуль, которому
  это разрешено), кватернион головы доступен каждый кадр.
* **Не хватает**: панорамирования относительно головы (Ambisonics или
  stereo→binaural через эффекты Media3 или OpenSL), громкости в виджете
  деки, аудио-метаданных источников.
* **Затрагивает**: `core-video` + виджет деки.

### 11. Morph-цели + сжатый glTF с Draco/KTX2 [roadmap]

* **Есть**: полный конвейер разбора/экспорта glTF, механизм каналов
  анимации (morph — просто ещё одна цель анимации: `weights`).
* **Не хватает**: разбора атрибутов morph (`extras.targetNames`, дельты
  POSITION/NORMAL/TANGENT), `MorphTargetBuffer` + `setMorphWeights` на
  стороне рендера; зависимости-декодера для Draco (например,
  `draco-android`) и KTX2 (basis-transcoder).
* **Затрагивает**: `core-scene` (разбор), `core-render` (Filament уже
  поддерживает и то и другое — `morphing(targetCount)` и устаревшие пути
  есть в API, которое мы уже исследовали).

### 12. Путь апгрейда до 6DoF [roadmap]

* **Есть**: `HeadPoseProvider.dof: DoF` (перечисление уже там),
  `RokidMaxBridge.UXR_ENTRY_CANDIDATES` перечисляет классы UXR SDK для
  поиска, обнаружение `uxrSdkPresent` работает уже сегодня; рендерер
  потребляет только кватернион — компонент позиции расширил бы тот же
  канал.
* **Не хватает**: подключения настоящей сессии UXR (`connectUxr` —
  заглушка с комментарием) или inside-out отслеживания с камеры телефона
  (`QuaternionPoseProvider.setOrientation` уже принимает ориентацию;
  позиция шла бы от визуально-инерциальной одометрии на телефоне).
* **Затрагивает**: в основном `core-bridge`; `RayCursor` и камера
  научились бы трансляции (станет возможен параллакс).

### 13. Отслеживание рук / контроллеров (Max Pro) [roadmap]

* **Есть**: разделение на производителя и потребителя было спроектировано
  именно для этого — README и документация `InputEvent` говорят:
  «отслеживание рук подключится здесь как ещё один производитель
  InputEvent; распознаватели останутся без изменений».
* **Не хватает**: источника отслеживания (hand API UXR SDK или на основе
  камеры), сопоставления жестов с `InputEvent`.
* **Затрагивает**: новый производитель в `core-bridge` или новый
  `core-hand`; `core-input` по замыслу не меняется.

### 14. Запись 3D-вида [roadmap]

* **Есть**: всё, что композитится, живёт в одном представлении Filament;
  Media3 уже является зависимостью.
* **Не хватает**: захвата `Surface` (`ImageReader`/`MediaRecorder` на
  surface swap chain напрямую невозможны — понадобится `readPixels` от
  Filament или виртуальный дисплей); конвейера кодирования в файл.
* **Затрагивает**: новый `core-record` + кнопку в HUD.

### 15. Обнаружение надетых очков + автозапуск при включении [roadmap]

* **Есть**: `MadgwickRokid` уже потребляет акселерометр/гироскоп по
  таймеру (`isInitializedFromAccel`); приложение стартует по intent
  подключения USB.
* **Не хватает**: классификатора активности по потоку IMU (устройство
  стоит / надето / снято), авто-паузы/возобновления видео и затемнения
  UI; приёмника загрузки + первоначальной настройки для headless-бокса.
* **Затрагивает**: `core-bridge` (классификатор), `:app` (жизненный
  цикл).

### 16. Полный экспорт материалов — `.mtl`, текстуры, расширения KHR [roadmap]

* **Есть**: `GltfExporter.toGlb` заново порождает PBR-коэффициенты,
  ссылки на текстуры и **оригинальные закодированные байты изображений**
  (дословно, без перекодирования); `toObj` пишет только геометрию.
* **Не хватает**: sidecar-файла `.mtl` для экспорта OBJ (Kd/Ks/Ns/map_Kd
  вычисляются из `GltfMaterial`); путей перекодирования текстур, когда
  источник не является переносимой байтовой blob (например, будущие
  декодированные/процедурные текстуры); **round-trip расширений KHR** —
  разбора и повторного порождения `unlit`, `clearcoat`, `transmission`
  (сегодня неизвестные расширения молча отбрасываются `GltfParser`,
  поэтому у моделей, например, `KHR_materials_unlit`, теряется их флаг).
* **Затрагивает**: `core-scene` (`GltfParser`, `GltfExporter`) + JVM-
  тесты round-trip. Естественный компаньон к #4 (импорт OBJ): вместе они
  замыкают цикл импорт↔экспорт для распространённых DCC-форматов.

## Долгосрочная / экспериментальная перспектива — названия для поиска [roadmap]

Кратко намеренно: перед любой оценкой каждое нуждается в собственном
исследовательском спайке:

* **Облачная синхронизация сцены** — сериализация рабочего пространства
  → загрузка → многопользовательские сессии; опирается на экспорт сцены
  (#6). Поиск: *glTF scene sync realtime collaboration*.
* **Плагинный API на AIDL** — загрузка функциональных модулей (панели,
  импортёры, игры) во время работы без пересборки хоста. Поиск:
  *Android AIDL plugin architecture, dynamic feature modules*.
* **Облачный рендеринг / удалённый GPU** — потоковый рендерер уровня
  десктопа внутрь 3DoF-хоста. Поиск: *WebRTC game streaming, CloudXR*.
* **Процедурный рельеф + растительность** — демо-контент поверх стека
  физика + glTF. Поиск: *procedural terrain heightmap Unity/Unreal style
  algorithms, GPU vegetation*.
* **Игровая логика ручной работы** — с #3 (события столкновений)
  песочница становится рантаймом мини-игр; поиск: *Jolt Physics gameplay
  events*.
* **Контент в стерео/3D-режиме** — `DisplayController.set3dMode` (#2)
  плюс рендер side-by-side; поиск: *Android stereoscopic 3D companion
  mode*.
* **Сессии с несколькими очками** — два моста одновременно (цепочка уже
  их абстрагирует) для общих сцен. Поиск: *multi-user AR shared anchor
  sessions*.

## Как выбрать

| Если вы хотите… | Начните с | Почему |
|---|---|---|
| Выпустить что-то заметное на этой неделе | #1 перетаскивание панелей, #8 оверлей сочетаний | чистые дельты в `:app`/`core-input`, без новых зависимостей |
| Сделать бокс настоящим гаджетом | #2 DisplayController, #15 обнаружение надетых очков | `core-bridge` изолирован; аппаратные протоколы живут только там |
| Привлечь контент | #9 веб-браузинг, #4 импорт OBJ, #11 сжатый glTF | контент появляется быстрее, чем мы успеваем моделировать его нативно |
| Сделать это платформой | #13 отслеживание рук, плагины AIDL, экспорт сцены | каждому сначала нужна работа над контрактами из `MODULES.md` §10 |
| «Вау» на митапе | персонажи уровня CesiumMan (#11 morph'ы), #3 игры на физике, #14 запись | уже на 80 % готово; запись делает результат делимым |
