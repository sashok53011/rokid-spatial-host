# rokid-spatial-host

Нативное Android spatial-приложение для AR-очков **Rokid Max** —
иммерсивное3DoF-окружение на Kotlin + Filament: сфера360°-видео,
парящие пространственные панели, glTF-модели с полноценными
PBR-материалами, физика твёрдых тел и экспорт моделей. Работает
исключительно мышью (целевая коробка без сенсорного экрана) и
управляет очками по **raw USB HID** — вендор SDK не требуется.

Проект представляет собой полный **конвейер прототипирования glTF**:

```
импорт (D1) → материалы/IBL (D2) → физика (D3) → экспорт (D4)
```

Всё ниже реализовано, проверено на реальном железе и закоммичено
пошагово (см. [историю Git](#roadmap--todo)), так что путь можно
воспроизвести.

## Требования

**Железо**

* Очки Rokid Max (3DoF, USB-C; HID id `04d2:162f`)
* Android12+ ARM64-коробка с USB host — разработано на Orange Pi
  5 Plus; подойдёт любая коробка, запускающая APK и умеющая читать
  interrupt-IN HID очков
* USB-мышь (обязательно), USB-клавиатура (рекомендуется — есть
  горячие клавиши)

**Программы**

* JDK17+
* Android SDK platform35 (Gradle-обёртка докачает остальное)
* `adb` в PATH

## Сборка и запуск (воспроизводимо)

```powershell
git clone <ваш-форк> rokid-spatial-host
cd rokid-spatial-host
.\gradlew.bat assembleRelease          # ~26 МБ, arm64, debug-ключ

# целевая коробка (подставьте ваш IP):
adb connect 192.168.0.173:5555
adb install -r app\build\outputs\apk\release\app-release.apk
adb shell pm grant com.rokid.spatialhost android.permission.READ_EXTERNAL_STORAGE
adb shell am start -n com.rokid.spatialhost/.MainActivity
```

Полезные фильтры logcat (каждая фаза пишет под своим тегом):

```powershell
adb logcat -s SpatialHost FilamentRenderer MaterialFactory ModelManager \
    IblBuilder PhysicsWorld RokidMaxBridge UsbDiagnostics
```

Первый запуск: разрешите доступ к хранилищу (он включает сканирование
локальных видео/моделей), воткните очки в USB коробки — мост
подключается сам, а360°-видео стартует примерно через3 с.

Напоминание: в `gradle.properties` зафиксирован **Filament1.75.1**
(для1.80.x нужен compileSdk37), **Kotlin2.4.x**, AGP из каталога
версий.

## Управление (дружелюбно к мыши без клавиатуры)

| Ввод | Действие |
|---|---|
| Перетаскивание мыши | Обзор (поверх трекинга головы) — **вращает выбранную модель**; в физике нажатие на модель **захватывает** её (drag = нести, флик = бросить) |
| Левый клик | Выбор модели под перекрестием, иначе панели (клик по пустоте = снятие выбора) |
| Двойной клик / правый клик | Recenter сессии |
| Средний клик / `V` | Вкл/выкл сферу360°-видео (фон ↔ живой поток) |
| Колесо | Следующий источник видео — **масштабирует выбранную модель** (×0.2…×6) |
| `M` | Следующая модель (демо → локальные файлы → …) |
| `P` | Вкл/выкл физику — модель падает на пол как твёрдое тело |
| `E` | Экспорт текущей модели как `.glb` + `.obj` в Загрузки (round-trip проверен) |
| `N` | Следующий источник видео |
| Клик по виджетам дека | Нижняя панель «Video»: PLAY/PAUSE · ‹SRC/SRC› · тумблер LOOP · слайдер SEEK (клик = перемотка) |
| `H` | Показать/скрыть HUD |
| `R` / стрелки | Recenter / циклический фокус панели |

### Рабочий процесс: модели

1. Киньте модели на коробку: `adb push MyModel.glb /sdcard/Download/`
2. Перезапустите приложение (или нажмите `M` после перезапуска) —
   `.glb`/`.gltf` сканируются из `/sdcard/Download`, `/sdcard/models`,
   `/sdcard/Documents`, `/sdcard/Movies` (внешние `.bin` рядом с
   `.gltf` тоже резолвятся).
3. Клик по модели — выбор, drag — вращение, колесо — масштаб, `M` —
   переключение источников.
4. `E` пишет `<имя>.glb` + `<имя>.obj` в Загрузки. Приложение тут же
   перепарсивает собственный GLB в памяти и пишет в лог
   `ROUND-TRIP OK` со счётчиками структуры; экспортированный файл
   импортируется обратно через `M`.

### Рабочий процесс: видео

Колесо/`N` переключает **360 equirect → LIVE HLS → ToS → PTS → bipbop →
BBB → локальные файлы**. Локальные видео сканируются из
`/sdcard/Movies`, `/sdcard/Download`, `/sdcard/DCIM/Camera`,
`/sdcard/video` (mp4/mkv/webm/mov/ts/avi/m4v). Любой `rtsp://` или URL
ExoPlayer добавляется в `PUBLIC_SOURCES` в `MainActivity.kt`. `V`
переключает сферу.

### Рабочий процесс: физика

`P` включает Jolt: модель становится динамическим боксом из её
масштабированных границ и падает на статическое пол (`y = -1`,
контакт точный: `y = пол + половина высоты`). Во время симуляции:

* нажатие **на модель** — захват (пружина тянет её к перекрестию плюс
  смещение от мыши в плоскости камеры),
* отпускание при движении мыши — **бросок**,
* повторное `P` — поза приземления сохраняется (позиция + yaw/pitch из
  кватерниона тела).

## Архитектура

```
app                     MainActivity, HUD, цепочка мостов, USB-разрешение,
                        жесты, связка модель/видео/физика/экспорт
core-bridge             контракт GlassesBridge / HeadPoseProvider
  ├─ rokid/             RokidMaxBridge — raw-HID3DoF (без UXR SDK)
  ├─ viture/            VitureHidBridge (USB-порт ar-bridge из VertoXR Web)
  └─ emulator/          EmulatorBridge (тач-обзор / гироскоп телефона)
core-render             FilamentRenderer (рендер-цикл, каналы отложенных
                        мутаций сцены), Meshes, MaterialFactory (filamat
                        рантайм), IblBuilder, ModelManager
core-scene              SpatialPanel, LayoutEngine, тесты лучей, GltfParser,
                        GltfExporter (чистый Kotlin, тестируется на JVM)
core-input              GestureRecognizer, RayCursor, NavigationState
core-video              StreamPlayer (ExoPlayer, узкие буферы низкой
                        задержки)
core-battery            ThermalGovernor (бюджет FPS), PowerReport (мАч)
core-physics            PhysicsWorld (Jolt через jolt-jni): тела, пружинный
                        drag
```

Ключевые паттерны:

* **Единственный контракт позы головы** — `HeadPoseProvider`; рендерер
  потребляет только `poseSupplier: () -> FloatArray` (кватернион), так
  что новые мосты (6DoF Max Pro, трекинг рук) встают без правок
  рендера/ввода.
* **Мутации сцены в рендер-потоке** — всё, что UI-поток хочет изменить,
  идёт через volatile-поля «pending» (`pendingModel`, `pendingPanels`,
  `pendingModelTransform`, запросы видео-сферы), потребляемые в начале
  рендер-цикла.
* **Материалы рантаймом** — исходники `.material()` компилируются на
  устройстве filamat (`MaterialFactory`), поэтому сборке не нужны ни
  `matc`, ни прекомпилированные `.filamat`-ассеты.

## Как это работает — заметки и подводные камни (для повторяющих)

Каждый раздел фиксирует неочевидные факты, нужные для воспроизведения.

### Мост Rokid Max по raw-HID

Очки отдают interrupt-IN HID-интерфейс с отчётами IMU `0x11` длиной
64 байта на ~450 Гц: **f32 accel с байта9, f32 gyro с байта21**,
устройственный фейм повёрнут на Rx(−90°) относительно мирового
(проверено офлайн-симуляцией и sanity-гейтом «уровень по акселерометру»
на старте). У моста есть детект зависания потока (3 с без пакетов →
переподключение), авто-возобновление и USB-detach receiver; строка HUD
`stream : pkt=… drop=…` делает мёртвый/дёрнутый кабель очевидным. USB-
устройство может держать только одно приложение — остановите
`com.rokid.spatialstudio` перед запуском этого.

### Сфера360°-видео

Материал `video_external` (filamat) семплит Filament `Stream`,
обёрнутый вокруг `SurfaceTexture`, кормимого media3. В шейдере сэмплеры
пишутся **макросом** `materialParams_<name>` (точечный синтаксис только
для uniform-параметров). Сфере — `culling(NONE)`.

**Подводный камень — перевёрнутое видео**: кадры приходят в GL-
ориентации (строка0 = низ), а панорамная конвенция ждёт v=0 сверху,
поэтому `getUV0()` надо инвертировать (`vec2(uv.x, 1.0 - uv.y)`) —
иначе весь360°-мир рисуется вверх ногами (вместо крыш сверху — вода).
Этот баг жил с Phase B2, пока его не поймали скриншотом уличной
панорамы.

### D1 — импорт glTF

`GltfParser` (core-scene) понимает контейнеры GLB, буферы `data:` /
внешние, bufferViews/accessors (f32/u16/u32, с шагом), иерархию узлов
`matrix` | TRS и считает границы модели, проходя по иерархии.

Решённые подводные камели (каждый стоил сессию отладки):

1. **Невидимая модель** — `IndexBuffer` обязан выделяться с *точным*
   размером в байтах (`indexCount * 2|4`). Хелпер, считающий «как
   float» (×4), заставляет Filament **молча отбросить draw** (без
   ошибки, ноль пикселей). Тот же класс бага был раньше в `Meshes.kt`.
2. **Нормали в Filament** — `VertexAttribute.NORMAL` не существует;
   нормали живут в атрибуте **TANGENTS** как кватернион-фрейм. Упакуйте
   `(tangent, bitangent, normal)` через `MathUtils.packTangentFrame(...)`;
   битанген = ±(n × t), знак — в `w` кватерниона (у glTF TANGENTS.w).
3. **Освещение** — интенсивность направленного света в люксах
   (110000 ≈ ясный день), направление — куда свет *travel*; экспозиция
   камеры — физическая `setExposure(sunny f/16)`. Без IBL металлы почти
   чёрные (исправлено в D2c).

### D2 — материалы и IBL

* **baseColor — sRGB** — грузите как `InternalFormat.SRGB8_A8` и
  оставьте линеаризацию GPU при сэмплировании (дешевле и корректнее
  CPU-LUT). Normal/MR-карты остаются обычным `RGBA8` (это линейные
  данные!).
* **UV0** должен быть объявлен у каждого lit-рендерабла; заполняйте
  нулями, если у модели его нет, — раскладка вершин останется валидной.
* **MR-сэмплирование**: `metallic = mrFactor * tex.b`,
  `roughness = clamp(mrFactor * tex.g, 0.04, 1)`.
* **Normal-карты** задаются в *тангент-пространстве* и **до**
  `prepareMaterial()` (см. пример normal mapping в доках Filament).
* **IBL (D2c)**:
  * окружение = процедурный equirect, отрисованный с *точно* тем
    маппингом, что у материала `equirectToCube` Filament:
    `u = 0.5 + atan2(x, z)/2π`, `v = 0.5 - asin(y)/π` (v=0 = зенит);
  * GPU-префильтр через `IBLPrefilterContext` из filament-utils:
    equirect → кубмап → `SpecularFilter` (мипы шероховатости) →
    `IndirectLight.reflections()`;
  * **AAR поставляет `libfilament-utils-jni.so`, но ни один Java-класс
    её не грузит** — вызовите `System.loadLibrary("filament-utils-jni")`
    сами;
  * у equirect-текстуры должен быть `SAMPLER_2D` и **полная mip-
    цепочка** (`levels == ilogb(width)+1`) с флагом `GEN_MIPMAPPABLE`,
    иначе `generateMipmaps` падает Precondition-паникой;
  * диффуз = SH3-го банда той же аналитической среды:
    `sh[i] = c_i · Ĉ_l · N_i / π`, где `Ĉ = [π, 2π/3, π/4]` (обрезанный
    косинус), `N` — константы полинома Слоуна — т.е. **«Fd_Lambert()
    запечён в SH»** (сверено с `CubemapSH.cpp` и поставляемым шейдером
    `Irradiance_SphericalHarmonics`; sanity-check: `sh[0]` равно
    средней освещённости окружения).

### D3 — физика (jolt-jni)

Зависимость: `com.github.stephengold:jolt-jni-Android:7.0.0:SpDebug@aar`.

Решённые подводные камни:

1. **`classes.jar` у SpRelease отрезан R8 до пустоты** в опубликованных
   релизах — компилируйтесь против **SpDebug**.
2. AAR объявляет **minSdk33**, а коробка — Android12 — добавьте
   `<uses-sdk tools:overrideLibrary="com.github.stephengold.joltjni" />`.
3. `JoltPhysicsObject.startCleaner()` требует `java.lang.ref.Cleaner`
   (**API33+**) — оберните в try/catch и явно `close()`-ьте временные
   нативные обёртки (формы, `BodyCreationSettings`); `RVec3`/`Quat`/
   `Vec3` — чистый Java и не текут.
4. Порядок инициализации важен: `loadLibrary("joltjni")` → аллокаторы →
   `newFactory()/registerTypes()` → таблицы слоёв → `PhysicsSystem.init`.
5. Dragging = пружинная сила `F = m·(kp·Δx − kd·v)` к точке-цели (собственный
   drag Jolt тоже пружина); масса оценивается из объёма бокса при
   плотности Jolt по умолчанию (1000 кг/м³).

### D4 — экспорт

`GltfExporter` воспроизводит то, что съел парсер: матрицы узлов, меши с
POSITION/NORMAL/UV0 и u16/u32-индексами (у POSITION-акцессоров обязательные
min/max), PBR-материалы, сэмплеры/текстуры и **оригинальные байты
изображений**, скопированные в BIN-чанк GLB дословно — поэтому текстуры
проходят round-trip без перекодировки. Чанки GLB выровнены по4 байта
(JSON — пробелами, BIN — нулями).

Запись в Загрузки идёт через **MediaStore** (флоу `IS_PENDING`) на Q+ —
берите MIME, чей канонический суффикс совпадает с файлом (например
`model/obj`, а не `text/plain`, иначе провайдер приклеит `.txt`).
Round-trip проверяется in-memory сразу после экспорта: перепарсить GLB и
сравнить счётчики примитивов/узлов/текстур/материалов.

### Заметка по вводу: тап vs drag

`moved` должен считаться от **кумулятивной** дельты с `ACTION_DOWN`,
а не от дельт событий — медленные перетаскивания (маленькие дельты,
например `input swipe` с большим duration или аккуратный человек)
раньше читались как тапы.

Также: drag-`ACTION_UP` обязан порождать `InputEvent.DragEnd` — иначе
распознаватель держит флаг `dragging` и **глотает следующий настоящий
клик** (симптом: приходится кликать дважды; в adb-скриптах `input tap`
сразу после `input swipe` ничего не делал).

### Виджеты панелей (видео-дек)

* `TextureSampler` **нативный** — val в companion создался бы в `<clinit>`
  *до* того, как `Filament.init()` грузит libfilament-jni, и упал бы с
  `UnsatisfiedLinkError: nCreateSampler`. Такие val держите `by lazy`
  (первое использование — на рендер-потоке после создания движка).
* Битмапы виджетов ложатся в UV панели **без** инверсии V (сырой
  `getUV0()`) — в отличие от видео-сферы, обычный `setImage`-аплоад уже
  совмещает верх битмапа с верхом панели. Ошибочное направление видно
  мгновенно: весь дек зеркален по вертикали; flip от видео здесь не
  переиспользуйте.
* Панели с `persistent=true` переживают скрытие при иммерсивном видео —
  в логе `3 hidden, 1 persistent` (дуговые панели исчезают, дек остаётся
  для управления).

### Skybox и тени

* Skybox переиспользует `IblBuilder.reflections` (mip0 = чёткое
  окружение): `Skybox.Builder().environment(...)`. В режиме skybox
  цветная сфера НЕ создаётся (`sphereEntity = -1`), все пути сферы
  проверяют `>= 0`. Видео работает как раньше — видео-сфера строится по
  требованию и прячет пол + дуговые панели (персистентный дек остаётся).
* Теням нужен **LIT-receiver**: неосвещённые панели игнорируют свет
  полностью, поэтому добавлен освещённый пол (`lit_pbr`, матовый,
  y = −1 = верх физического пола) — без него модель кастит в пустоту.
  Проверено прямым солнцем (тестом): силуэт шлема ложится на пол; при
  штатном наклоне (выровненном с солнцем IBL) тень лежит за деком и
  видна сбоку.
* Ловушка алиасинга: несколько вызовов `updatePanelUi` с ОДНИМ буфером
  пикселей — все панели показывали последнюю отрисовку; канал теперь
  клонирует пиксели.

## Советы по отладке

* **Скриншоты**: PowerShell `>` портит бинарник — используйте
  `cmd /c "adb exec-out screencap -p > shot.png"` (магия PNG должна
  начинаться с `89-50-4E-47`).
* **Гонки прицела**: очки на живой голове; любой скриптованный
  `input swipe` соревнуется с IMU. Сделайте recenter (`keyevent46`) и
  читайте строку `diag: look=(…)` рендерера (пишется каждую секунду) —
  она показывает, куда реально смотрит камера.
* `input swipe x1 y1 x2 y2 duration` даёт настоящие MOVE-события —
  удобно для проверки drag-логики; `input tap` — тап;
  `input keyevent <код>` для клавиш (`E`=33, `M`=41, `N`=42, `P`=44,
  `R`=46, `V`=50).
* Рендер-цикл пишет `diag: vp=… entities=… renderables=…` —
  пропавшая модель видна как заниженный `renderables` ещё до пикселей.
